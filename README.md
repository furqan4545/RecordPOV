# RecordPOV

RecordPOV is a native iOS and Android app for recording yourself alongside videos, photos and screen recordings. The hosted API is `https://api.recordpov.app`. The first screen focuses on adding a video or photo; screen recording lives in its own **Screen** tab.

## Start

- **iOS:** open `apps/ios/Roast.xcodeproj`, or run `npm run ios`. Requires Xcode 26+ and iOS 26+. The helper reuses the existing **iPhone 17** simulator and never creates another device.
- **Android:** open `apps/android` in Android Studio, or run `npm run build:android` with JDK 17+ and the Android SDK configured. Supports Android 10+. The debug APK is `apps/android/app/build/outputs/apk/debug/app-debug.apk`.
- **Video links:** both apps use `https://api.recordpov.app`. The apps can import local videos and photos without the service.

The media service runs on Hetzner under `/opt/recordpov`; deployment and access details are in [server/deploy/README.md](server/deploy/README.md). Existing app installations migrate the former Mac/emulator defaults once, while preserving custom service addresses. Projects, recordings and exports remain on the device. The server keeps a bounded temporary source-video cache; no R2 storage or Mac service is required. Optional local testing is described in [server/README.md](server/README.md).

The November 6 preparation release passed 65 tests on Linux and reuses compatible source video/audio instead of encoding every import. For one 64.7-second Instagram clip, cold server fetching and preparation fell from 41.358 seconds to 5.419 seconds; the subsequent phone download is excluded. See [the benchmark](docs/verification/import-cold-performance.json) and [deployment verification](docs/verification/hetzner-deployment.json). The current native clients use `/v2/media/resolve` to download compatible source files directly to the phone and join split video/audio locally. Prepared cache hits and unsupported formats retain the server path. Actual downloads use iOS background URLSession or Android’s data-sync foreground service; projects and completed imports remain local. See [the delivery contract](server/DIRECT_DELIVERY.md) and [device verification](docs/verification/direct-delivery-platforms.json).

**My videos** has a two-option switch at the top: **Saved videos** (selected by default: finished videos and unfinished edits) and **Imported videos** (downloaded or uploaded source videos). The app commits a durable local copy of every import before opening Studio, so an import reopens later without the media service, including after relaunch, an app update or the server cache expiring; if its file is gone, the app says so and asks for the link again instead of opening a broken Studio. Create keeps the add-media flow together: a URL field, Download & open video, an or divider, and Upload video or photo. The **Recent** section below shows only imported videos as tappable thumbnails. Existing imports reopen from Recent instead of adding a saved-video action to the URL card.

## Optional accounts

Apple and Google sign-in live in **Settings → Account**. Authentication uses the existing Hetzner server and a private SQLite database under `/opt/recordpov-auth`, with no Supabase project or auth subscription. Recording and local projects remain available without signing in. Native sessions use iOS Keychain or Android Keystore-backed encryption; account deletion retains local videos. See [auth/README.md](auth/README.md) for provider setup and deployment.

iOS uses Google’s official Sign-In Swift package. Simulator helpers use ad-hoc signing so Keychain works during UI checks; the physical app uses the existing Apple development team.

## Recording flow

Opening a link shows its real progress under the button, plus one short instruction. On iOS it reads “Keep RecordPOV open until your video is ready.” from the lookup until the video opens: a progress bar with the percentage appears as soon as bytes arrive, and during “Almost ready…” a moving bar shows the last step is still working. When the video is ready, the status fades out and Studio opens it by itself. iOS never starts a download while the app is in the background (iOS would defer such transfers), and the last step runs only while the app is open, so leaving pauses the import until you return. On Android the whole import runs in a foreground service, so it shows “You can leave RecordPOV. It keeps going in the background.” from the start; if an import finishes while you are away, Create shows “Your video is ready” with Open and Dismiss instead of opening Studio by surprise. Videos are local before recording begins.

1. Paste a public Instagram, YouTube, X or TikTok video link, or choose a video/photo.
2. Enter Studio with your front camera on and **Cutout** selected. Camera capture starts only on Studio entry; a device without a camera still opens the source normally. Choose **Small camera**, **Split** or **You on Stage** from the layout menu. Split keeps the entire original visible above your camera, with a softened background filling aspect-ratio gaps; its divider ranges from 20–80% (70/30 by default). Returning from Split to Small camera uses **Rounded** after Cutout, while other explicitly chosen shapes and placement are preserved. New editor microphone levels start at **60%**; saved custom levels stay unchanged. One finger moves an overlay; two fingers resize and rotate it with gentler sensitivity. Lifting one finger immediately returns to dragging. You on Stage makes your camera the main video, with a movable original-video overlay. The fullscreen button temporarily expands your camera and restores the previous layout and placement.
3. Tap Record for a three-second countdown. The timer control offers Off, 3, 5 or 10 seconds and remembers your choice. Countdown can be canceled; it is excluded from the saved video. Source playback begins with recording, from your current position (or restarts if it has ended). Pause/resume/seek only the source while camera and voice keep recording. When the source ends, its last frame stays visible until you manually finish your take.
4. Add pictures during the take. Switch back to the original video using the source tray.
5. Finish recording to open the editor. Adjust your voice, original-video audio and imported music independently. In **Trim**, drag the thumbnail strip's start and end handles; the video immediately shows the frame at the edge you are moving. Save exports exactly the continuous section between the handles. **Reset trim** restores the full recording. Preview uses the same audio mix and captions as final export.
6. Save the edited video, then preview and share it. Finished H.264/AAC takes automatically save to Photos on iOS or Gallery on Android, and remain in My videos. iOS asks once for add-only Photos permission. If Photos/Gallery saving fails, the app copy stays safe and offers a retry; successful saves are remembered to avoid duplicates.

The editor keeps the original recording and isolated microphone/source stems as an app-private draft until the final video is saved. Going back preserves the draft and edits; reopen it from **My videos**. Captions are optional and use only the microphone stem, never the digital original-video/music mix. On iOS, **Generate captions** requests Speech permission and uses Apple's on-device speech models, downloading the selected language if needed. Android explicitly offers a verified 104 MB Whisper tiny download on first use and performs recognition locally; its caption intervals follow measured microphone speech segments. Both editors allow text corrections and include captions in preview and exported video. Audio is not uploaded for transcription.

**Clean voice** in Audio gently reduces steady microphone hiss and low-frequency rumble. It is enabled for new takes; older drafts preserve raw audio until explicitly enabled. Switching it off restores the original microphone stem. Preview and export share the same cached cleanup, while the raw mic remains available for captions. The digital source and music are never filtered. Cleanup preserves the original clock, gaps, silence and duration; it does not claim to separate arbitrary voices already mixed acoustically by the phone speaker. Headphones remain the reliable way to avoid that bleed.

Live recording requests and verifies echo cancellation after session activation, microphone attachment and route changes. iOS retains Apple's wider-band default-mode input, with supported AirPods high-quality recording and HFP fallback. Android verifies live AEC and NoiseSuppressor effects against the recorder session and rebinds them after route/session changes. These paths preserve input timing and avoid added gain boosts or hard noise gates. The physical iPhone reported echo cancellation enabled on its built-in mic/speaker route at 48 kHz; the metadata-only report is `docs/verification/microphone-route-iphone.json`. No samples were captured by that check.

In PiP, drag, pinch and rotate your camera; choose rounded, circle, square or Cutout. Regular shapes fill edge to edge. **Wider / Closer** adjusts framing independently of overlay size, and **Flip** switches cameras. On supported front Ultra Wide cameras, Split requests a landscape crop from the square sensor while PiP, Stage and fullscreen use portrait framing; changing the crop keeps the capture session and microphone running.

The preview and export use native compositors. iOS uses AVFoundation, Core Image and Apple's Vision person segmentation. Android uses CameraX, EGL/MediaCodec, Media3 and bundled ML Kit selfie segmentation. Background removal runs on-device; camera footage and finished takes are not uploaded to the media service.

Cutout on iOS uses Vision's **Accurate** quality with matting refinement, the highest runtime-supported person-segmentation revision, and floating-point masks when supported. Masks resize independently along each axis to match the exact camera image and blend through their red channel; soft confidence values are preserved. The processor resets its history when the camera changes or Cutout is re-entered. Android preserves raw ML Kit confidence with bilinear mask resizing and resets its streaming history at the same boundaries. The bundled Android selfie model is `16.0.0-beta6`, currently the latest published Google Maven version; this is an alpha-processing improvement rather than a model replacement.

## Screen recording: platform behavior

**Android** records the display through MediaProjection and shows a movable camera window over other apps. It requires the OS's capture consent, overlay approval, camera/microphone permissions and a visible foreground-service notification. The current screen mode records microphone narration; it does not digitally capture other apps' audio. Protected content can appear blank.

**iOS** uses a user-started ReplayKit Broadcast Upload Extension to save the screen first; the user then adds their camera reaction in the studio. It also accepts existing screen recordings. iOS does not provide the requested arbitrary floating camera overlay over other apps for this mode. The app explains the two-step flow before recording.

Device signing is configured for the existing development team, using `com.furqanali.roast` and the dedicated shared group `group.com.furqanali.roast`. Both the app and screen-recording extension use that group. To change identifiers, update `ROAST_APP_BUNDLE_ID`, `ROAST_APP_GROUP_ID` and the shared entitlements file. The Broadcast Picker derives the extension identifier from the installed app's bundle identifier.

Physical and simulator builds default to `ROAST_MEDIA_SERVICE_URL=https://api.recordpov.app`. A different service address can be supplied explicitly for development. Build output should live outside iCloud-synced Desktop folders to avoid Finder metadata interfering with code signing.

## Checks

```sh
npm run test:auth
npm run typecheck:auth
npm run test:media
npm run typecheck:media
npm run test:android
npm run test:ios
```

iOS UI checks cover example-studio entry, layout selection with camera off, the recording timer, independent editor controls, draft recovery and invalid-link feedback that preserves input. The public-link integration check uses the hosted service, with an optional `ROAST_TEST_MEDIA_SERVICE_URL` override. Parallel simulator testing is disabled so Xcode reuses the existing iPhone 17. Camera appearance, acoustic echo, live cutout edges, sustained capture performance and screen-capture services still require physical-device acceptance before release.

The media service has bounded imports, Range playback, cache expiry and configurable limits. Private/authenticated, removed, restricted or platform-blocked videos may not be importable; local imports remain available. Review its deployment boundary before exposing the resolver publicly.

The hosted default uses HTTPS and does not require the Mac or shared Wi-Fi. The server only finds a video's direct links; it never downloads or stores the video, which the phone downloads itself. On iOS, TikTok is looked up on the phone like a browser (the page's cookie is sent with the download), so the server is not used for it. YouTube lookups use the foreground phone's connection through an isolated Hetzner worker running yt-dlp; on iOS the YouTube files then download in 10 MB pieces, and a piece that receives nothing for 30 s is requested again. Keep the app open until importing finishes. This carries only public-source traffic, never camera, microphone or project data. The supplied seven-minute YouTube link passed a complete uncached import into Studio on the physical iPhone, and the Android production transport passed a full live download and decode. See `docs/verification/youtube-phone-imports.json`; other-platform results are in `docs/verification/hetzner-media-imports.json`. Optional local endpoints retain specific Local Network diagnostics.

iOS camera switching now replaces inputs transactionally, restores the prior camera after a failed flip, and configures the committed output connection. Front capture prefers the Ultra Wide camera where available, with a Wide camera fallback, and starts at minimum hardware zoom. A retained rotation coordinator handles each sensor's orientation; the physical check confirmed front → back → front with fresh 720×1280 frames, rotation 0° → 90° → 0°, and mirroring only on the front camera.
